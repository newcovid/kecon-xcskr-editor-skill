# POU变量作用域与编译可见性

## 必须区分的两个作用域

| 位置 | 可采用的变量入口 | 不采用的写法 |
|---|---|---|
| PROGRAM程序 | 工程变量表中登记的全局变量、既有结构字段及硬件标签 | 在PROGRAM下添加SECTION_VAR_INPUT/OUTPUT/INTERNAL后直接使用其名称 |
| 自定义ST FUNCTION_BLOCK | 块自身声明的输入、输出和内部变量 | 直接引用工程全局变量；需要的数据通过已声明引脚传入，结果通过输出引脚发布 |

**证据：厂家GUI编译日志。** V5.1.1.9998-C未识别PROGRAM内部的变量声明，
即使这些声明已写入XML、能正常导出且原有静态检查通过。错误1025指向变量名，
并伴随583/1047/1067等连带错误。自定义ST块直接访问工程全局结构也曾出现编译错误。
这些是已观察到的编译作用域限制，不能把XML可解析或CLI接受参数当作厂家支持。
其它厂家版本的PROGRAM内部变量支持情况未验证；本安全编辑工具不生成该类声明。
扩展支持前应先取得目标版本的厂家编译证据并补对应测试。

## 新增程序变量时

1. 按现有工程的数据职责选择全局变量或结构字段，不要求所有工程统一使用某个固定结构名。
   给出中文含义、单位、写者及跨扫描状态的初始化/复位方式。暂存和循环下标不得跨任务共写。
2. 新增结构字段后，重建所有承载该类型的变量成员树；同时核对类型声明及展开变量，
   数组长度、元素类型、字段描述和引用路径应一致。保留既有成员与逐元素描述。
3. 组态完成后重新导出，再修改ST为已登记的限定路径；对齐、预演并按manifest保护回灌。
   不靠修改只读声明视图、补一份独立测试环境变量或强制导出掩盖真实工程漏登记。

例如，既有全局`State`变量类型为`RunState`时：

```powershell
python ... add-user-struct-member --project P --struct RunState --member "Elapsed_ms:UDINT:主任务控制程序专用，经过时间ms"
python ... rebuild-variable-members --project P --name State
```

程序使用`State.Elapsed_ms`；自定义块若需要该时间，调用方通过其输入引脚传入。
不要为修复程序变量登记而扩大功能块的全局访问能力，也不要随意改变已有公开引脚顺序。

## 工具防护与验证边界

- `add-pou-var --pou-type program`在写入和备份前拒绝，包含`--dry-run`；
  函数/功能块声明仍沿原接口处理。没有强制绕过此限制的开关。
- `validate-pou-scope`报告已有PROGRAM内部声明，以及自定义ST块对已登记工程全局变量
  或硬件标签的直接引用；跳过注释、字符串、成员名和调用引脚标签，尊重块内同名声明。
  `check-workspace`包含该检查。
- 该检查覆盖上述已知作用域边界，不是完整ST编译器，也不保证能找出所有未定义名称。
  数值测试必须执行真实维护ST，并另外核对真实工程的声明及变量成员树。
- 静态检查、数值执行、厂家GUI编译、设备下载及现场验证分别报告。
  原编译日志只证明修复前的错误；修改后的工程需重新编译，不能沿用旧成功结果。
